## 1. 회고란?

팀이 정해진 기간 동안 해왔던 일에 대해 돌아보며, 팀원들이 함께 생각하고 배우는 시간이다.

> **정의**: "팀 단위 자기 성찰" — Retrospective · Reflection · Postmortem

팀은 회고를 하면서 눈 앞에 보이는 이익뿐 아니라 능력과 기쁨이 증가하는 경험을 맛볼 수 있다. — *애자일 회고*

### 핵심 질문 4가지

| # | 질문 (영문) | 질문 (국문) |
|---|---|---|
| 1 | What were we trying to accomplish? | 무엇을 성취하고자 했는가? |
| 2 | Where did we hit (or miss) our objectives? | 어디까지 목적을 달성(미달성) 했는가? |
| 3 | What caused our results? | 무엇이 그런 결과를 만들었는가? |
| 4 | What should we start, stop, or continue doing? | 무엇을 새로 시작하고, 그만두고, 지속해야 하는가? |

## 2. 좋은 회고를 위한 Tip

### Tip 01 — 기술 + 사람, 함께 다룬다

"프로젝트"와 "팀워크" 두 축을 함께 바라보는 시각이 필요하다.

- 기술적 측면만 논하면 회고가 메마른다.
- 사람 측면만 다루면 방향을 잃는다.

### Tip 02 — 심리적 안전감이 중요

솔직하게, 하지만 가혹하지 않게. 다음 네 가지를 지향한다.

- 더 작고 · 더 목표지향적인 피드백
- 덜 개인적이고 · 덜 비판적인 피드백

> **결론**: 영향력 있는 피드백을 위해서는 심리적 안전감이 선행되어야 한다.

### Tip 03 — 실행하려는 의지

Action Item을 구체적으로 정하고, 다음 회고 때 실행 여부를 반드시 확인한다.

> **주의**: 아무리 좋은 의견도 실천 없이는 의미가 없다.

## 3. 회고 방법론

### 방법론 개요

| 방법론 | 항목 구성 | 특징 |
|---|---|---|
| KPT | Keep · Problem · Try | 잘 된 것을 유지하고, 문제점을 파악해 개선을 시도한다 |
| Continue-Start-Stop | Continue · Start · Stop | 계속할 것 / 시작할 것 / 멈출 것으로 행동을 분류 |
| 4Ls | Like · Lacked · Learned · Longed for | 네 가지 관점으로 팀 경험을 정리 |
| YWT | Yatta · Wakata · Tsugiyaru Koto | 잘 됐어! / 알게 됐어! / 다음엔 이렇게! |

### KPT 방법론 상세

KPT는 팀이 Keep(잘 한 것) · Problem(문제점) · Try(개선 시도) 세 관점으로 경험을 구조화하는 회고 방법론이다.

#### K — Keep : 잘 되고 있는 것, 계속하자

**핵심 질문**

- 팀이 잘 수행한 것은 무엇인가?
- 앞으로도 유지하고 싶은 좋은 습관은?
- 팀워크·프로세스에서 효과적이었던 것은?

**예시**

- 매일 스탠드업 미팅이 효과적이었다
- 코드 리뷰 피드백이 명확했다
- 일정 내 기능 완료

#### P — Problem : 문제점, 개선이 필요한 것

**핵심 질문**

- 어려웠거나 잘 안 된 것은 무엇인가?
- 팀의 생산성을 저해한 요소는?
- 반복되는 문제나 갈등은 없었나?

**예시**

- PR 리뷰 지연으로 병목 발생
- 요구사항 변경이 잦았다
- 커뮤니케이션 미스로 재작업

#### T — Try : 다음에 시도할 개선 행동

**핵심 질문**

- Problem 해결을 위해 무엇을 시도할까?
- 구체적이고 실행 가능한 행동은?
- 다음 스프린트에 바로 적용할 것은?

**예시**

- PR 리뷰 SLA 24시간 설정
- 데일리 미팅 시 블로커 먼저 공유
- 요구사항 변경 프로세스 정의

### KPT vs 4Ls 방법론 비교

| 비교 항목 | KPT (Keep · Problem · Try) | 4Ls (Like · Lacked · Learned · Longed for) |
|---|---|---|
| 항목 수 | 3개 (K · P · T) | 4개 (Like · Lacked · Learned · Longed for) |
| 중점 | 행동 개선 중심 | 경험·감정 공유 중심 |
| 구조 | 현재 상태 진단 → 해결책 도출 | 좋은 점 / 아쉬운 점 / 배운 점 / 바람 공유 |
| Try / Longed for | 바로 실행 가능한 행동 도출 | 희망 사항 (실행 선택) |
| 적합 시점 | 스프린트·프로젝트 마무리 | 팀 관계 형성·초기 회고 |
| Action Item | Try = Action Item 직결 | 별도 선정 과정 필요 |

> **결론**: 이 과정에서는 KPT를 사용한다. Try 항목이 곧 팀의 Action Item이 된다.

## 4. 회고 진행 절차

### STEP 1 — Check-In (3분)

각자 현재 감정·상태와 간략한 이유를 돌아가며 말한다. 서로의 상태를 파악하고, 발언 시 감정적으로 되지 않도록 주의한다.

**컨디션 척도 (1~5)**

| 점수 | 상태 |
|---|---|
| 1 | 매우 힘듦 |
| 2 | 조금 힘듦 |
| 3 | 보통 |
| 4 | 좋음 |
| 5 | 최고! |

**예시 발언**

- "오랜만에 교육을 들으니 설레요, 5점이 아닌 이유는 배가 고파서요" (4점)
- "늦게까지 프로젝트 하느라 잠을 못 잤더니 피곤해요, 1점이 아닌 이유는 퇴근 시간이 다 되어서 기뻐요" (2점)

### STEP 2 — 자료 모으기 (15분) : KPT Post-it 작성

1. Keep · Problem · Try 항목별로 색상을 다르게 사용한다 (예: 초록 · 빨강 · 주황)
2. 하나의 Post-it에는 한 가지 내용만 적는다
3. K · P · T 항목당 하나 이상씩 작성한다

### STEP 3 — 비슷한 생각들 정리 & Try 선정 (25분)

1. 이젤 패드를 Keep / Problem / Try 세 부분으로 나눈다
2. 각 항목별로 비슷한 생각들을 모은다
3. 개인별로 다른 생각들을 왜 그런지 들어보는 시간을 가진다
4. Try 항목 중 가장 중요한 것을 팀 Action Item으로 확정한다

> **주의**: Action Item은 Try 항목 중 다음 스프린트에서 실행할 구체적인 개선 항목으로 선정한다.
