# logs/README.md

## 개요

세션별 작업 과정을 기록하는 작업 일지이다.
의사결정 근거, 사용자 요청 이력, 시도 및 폐기 내역을 담으며
BP.md 4장(AI 활용) 및 5장(트러블슈팅) 작성 시 주요 참조 자료가 된다.

sessions/ 의 세션 파일과 1대1 매칭된다.

```
.ai/sessions/step2-red/step2-red_session_01.md
logs/step2-red/step2-red_session_log_01.md
```

## 로그 파일 구조

각 로그 파일은 아래 구조를 따른다.
파일명의 `{번호}`는 `01`, `02` 형식의 2자리 순번을 사용한다.

```markdown
# {단계}_session_log_{번호} | {날짜}

## 단계
현재 TDD 단계 (예: step2-red)

## 사용자 요청 이력
- 세션 중 사용자가 요청한 작업 및 변경 사항을 순서대로 기록

## 의사결정 내역
- 결정 사항과 그 근거
- 예: "employee_store.py 수정 방식 A 대신 B 채택 — 이유: 불변 규칙 위반 방지"

## AI 제안 채택/거부 내역
- 채택: 제안 내용 및 채택 이유
- 거부: 제안 내용 및 거부 이유

## 시도 및 폐기 내역
- 시도했다가 폐기한 방향 및 이유

## 생성물 목록
- 이번 세션에서 생성된 파일 및 문서 목록

## 주요 컨텍스트
- 다음 세션 또는 BP.md 작성 시 참조할 인사이트
- 반복된 문제 패턴, 팀 협업 관련 메모
```

---

## 세션 종료 시 — 로그 저장 프롬프트

세션 종료 전 아래 프롬프트를 AI CLI 에 입력하여 로그 파일을 생성한다.

```
현재 세션의 작업 로그를 아래 규칙에 따라 저장한다.

저장 경로:
- .ai/logs/{현재단계}/{현재단계}_session_log_{번호}.md

파일 구조는 .ai/logs/README.md 의 ## 로그 파일 구조 를 따른다.

포함 내용:
1. 세션 중 사용자 요청 이력 (순서대로)
2. 주요 의사결정과 그 근거
3. AI 제안 중 채택/거부 내역 및 이유
4. 시도했다가 폐기한 방향
5. 이번 세션에서 생성된 파일 및 문서 목록
6. BP.md 작성 시 참조할 인사이트 및 주요 컨텍스트

세션 번호는 동일 단계의 직전 로그 파일 번호에서 1 증가한다.
```

## sessions 와 logs 의 관계

| 항목 | sessions/session | logs/log |
|---|---|---|
| 목적 | AI CLI 작업 인계 | 사람이 읽는 작업 일지 |
| 주요 독자 | AI CLI | 팀원, 본인 |
| 핵심 내용 | 다음 시작점, 미완료 항목 | 왜, 어떻게 결정했는가 |
| 작성 시점 | 세션 종료 직전 | 세션 중 수시 또는 종료 후 |
| BP.md 참조 | 간접 참조 | 4장 AI 활용 / 5장 트러블슈팅 직접 참조 |
